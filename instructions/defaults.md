# Instructions — Defaults

Долгоживущие правила, подключаемые через `opencode.json → instructions`.
Один файл — одна тема. Не смешивай с `AGENTS.md`: там проект, здесь — как работать.

## Порядок работы

1. Прочитай `AGENTS.md` и релевантный файл из `docs/stages/`.
2. Сформулируй план. Код до этого момента не трогай.
3. Уменьши scope до минимального инкремента с демонстрируемым результатом.
4. Реализуй ровно согласованный объём.
5. Запусти минимально достаточную верификацию.
6. Проведи отдельный review-проход.
7. Заполни stage report.

## Спецификации

- `docs/specs/*.md` подключены в контекст автоматически. Читай их как источник истины.
- Если задача меняет игровой или сетевой контракт — **сначала** обнови spec, потом код.
- Расхождение spec и кода — это `contract drift`, его надо либо закрыть, либо явно зафиксировать.

## Плагин `plan`

В `opencode.json` для `plan` выставлен `edit: deny`. Это намеренно: plan не должен менять файлы.

Если плану нужно зафиксировать спецификацию:
- вызови субагента `system-analyst` (у него `edit: allow`), либо
- переключись в `build` и обнови spec отдельным инкрементом.

## Unity

- Unity Editor должен быть запущен и подключён к MCP bridge, иначе верификация невозможна.
  Если он не запущен — явно пиши `Not verified: Unity Editor не запущен`, не выдумывай результат.
- После изменения скриптов всегда: `recompile(focus=false)`, затем `console(level="error", tail=50)`.
- Не полагайся на память об Unity API. Проверяй через `mcp__unityMCP__eval` и `unity docs`.
- Никогда не редактируй `.unity` и `.prefab` как текст.

## Git

- Проект под git. `.gitignore` — Unity-шаблон. `.meta` коммитятся.
- Коммит создаётся только по явной просьбе пользователя.
- `git push`, `git reset --hard`, `git clean` запрещены политикой проекта.
