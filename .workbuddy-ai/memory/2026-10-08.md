# 2026-10-08

## Раскладка диалогового арта по папкам-пулам

Автор поставил задачу: завести папку под диалоговый арт, разбить по
категориям, разложить то, что уже нарисовано, и завести **все остальные**
папки — чтобы следующим этапом генерировать «в каждую папку под её
категорию». Перед работой попросил описать план и одобрил три решения.

**Решения автора (одобрены):**
1. Арт живёт в `Assets/Woodberry/Art/Dialogue/` — внутри проекта, с импортом,
   `.meta` и версионированием. Не склад вне `Assets`.
2. Имена файлов — `PascalCase` по `asset-standards.md`:
   `<Пул>_<NN>_<Стиль>.png` (`Priest_01_Ink.png`). Номер сохраняет связь с
   прогоном стенда, но id вида `01_priest_ink` в проекте не живёт.
3. Две роли-сироты (портреты есть, роли в каталоге нет) — **добавить роли в
   каталог**, а не подгонять под чужие пулы.

**Категории не выдуманы, а взяты из GDD.** Роли — из `04-levels.md`
(«Роли при зданиях», «Странники», «Ремесленники»), пулы — из `07-art-audio-ux.md`
(«Пулы портретов»). Общие жители — шесть пулов: пол × возраст. Городские NPC —
авторские, статичные. Угроза — не роль, а надстройка; пул только под истинный
облик.

**Структура:** `Dialogue/Portraits/{Roles,Wanderers,Craftsmen,Villagers,City,Threat}`
и `Dialogue/Backgrounds/{City, Village/{Interiors,Exteriors,Wilds}}`.
**88 папок-пулов**, заполнено 15 портретов и 7 фонов.

**Группу `Backgrounds/City` пришлось переделать по дороге.** Сначала я назвал
её по догадке (`Market`, `Alchemy`, `Gate`), потом нашёл в `04-levels.md`
таблицу «Особые объекты города» и привёл к ней: `Guild, Merchant, Forge,
Alchemist, Cathedral, CarriageYard, HunterHouse, Monastery, Inn`. Урок: перед
тем как придумывать имя папки, искать таблицу в доке.

**Источник кадров — `portraits/out`, не `deliver`.** Сверил побайтово:
`deliver` собран 06.10, а в `out` персонажи 11–14 **перерисованы** (там
доехали правки промпта: тёмная одежда у парня и девушки) и только там есть
`15_merchant` и `bg_swamp`. То есть `deliver` — не «свежее», а «то, что
отдавали раньше». Проверять это, а не верить названию папки.

**Дефект, найденный по дороге.** Те самые 11–14 в `out` были `512×768` вместо
стандартных `480×720` — их перерисовали после утверждения размера, и габарит
остался старым. Габарит — часть контракта, поэтому приведены к стандарту тем
же алгоритмом, что `check_sizes.py --fix` (`fit_cover`, LANCZOS, пропорция
2:3 → обрезки нет). Стенд не трогал: правка легла только в проект.

**Проверено:** `check_sizes.py` на временной копии с именами по правилам
стенда — `22 ок, 0 замечаний`, exit=0. Импорт Unity: 22 `.meta` создал сам
редактор (вручную не писались), и **до настройки Unity держала дефолт
`Default` с mipmap** — для диалогового кадра это неверно. Настроено через
MCP `execute_code`: `Sprite / Single / PPU 128 / Bilinear / mipmap off /
FullRect / Uncompressed`, проверка `22 из 22 спрайтов загружаются`. Консоль
чиста (одно старое предупреждение про Input Manager).

**Unity Editor пришлось запустить самому** — он не был открыт, а `.meta` и
импорт без редактора не появляются. Путь: `F:\Unity\Editor\6000.6.3f1\Editor\
Unity.exe -projectPath`. Мост MCP поднялся вместе с редактором.

## Что дальше

Генерация арта в каждую папку: расширить `scene.py` списком ролей из
`04-levels.md` и **восстановить сетку осей** — она даёт разнообразие внутри
пула, без неё из одного священника «разных священников» не выйдет. Инструмент
сетки утрачен при уборке стенда, принцип сохранён в памяти.
