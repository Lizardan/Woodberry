  `unityMCP_script_apply_edits`, `unityMCP_refresh_unity`, `unityMCP_run_tests`,

- Остаётся **чтение**: `read_console`, `unity_reflect`, `unity_docs`, `get_test_job`,
  `manage_tools` + ресурсы (`mcpforunity://editor/state`).
- Причина: `edit: deny` **не покрывает MCP-инструменты**, а `execute_code` — это
  произвольный C# через Roslyn. Теперь read-only у `plan` и ревьюера настоящий.

Механика OpenCode (из схемы установленного SDK, `types.gen.d.ts`): `permission`
принимает произвольные ключи — имена инструментов/паттернов — со значениями
`allow`/`ask`/`deny`; у агента есть `tools: { "<имя>": boolean }`. `tools: false`
убирает инструмент из контекста, `permission: deny` только блокирует вызов.

## Переделка интерфейса арт-студии

Пользователь увидел два набора кнопок «принять/отклонить» и прочитал это как
дубль; интерфейс не объяснял, что за что отвечает. Разобрался и переделал.

**Настоящий баг, а не только дубль.** Список кандидатов строился из событий
драйвера и не сверялся с диском: в окне висел `bg_City_Bathhouse`, файла
которого нет, а лежавший в `review/` `p_Craftsmen_Baker_c` не показывался
вовсе (события нового прогона начинаются с чистого листа). Починено новым
`ReviewScanner` — кандидаты читаются с диска, событие только повод
пересканировать. Пометка брака теперь снимается по времени файла (файл новее
пометки → кадр перегенерирован), а не по событию, которое теряется с
перезапуском.

**Дубль оказался не дублем, а двумя объектами:** кандидат (файл в `review/`) —
«принять» значит ПЕРЕНЕСТИ файл; кадр проекта — «принять» значит ЗАПИСАТЬ
отметку. `ArtStatus.Approved` читают только счётчик, фильтр и бейдж — драйвер
на него не смотрит.

**Новая раскладка.** Слева только дерево + блок пула (Сгенерировать, доп.
кадры); в центре первым разделом «На ревью (N)», ниже «В проекте (M)»; справа
один объект с заголовком («Кандидат · ещё не в проекте» / «Кадр проекта») и
взаимоисключающими наборами действий. Подписи: «Принять в проект» / «Отклонить
и перегенерировать» против «Отметить принятым» / «Пометить браком». Принятие
кандидата само отмечает кадр принятым. Комментарий виден только у брака.
Покрытие — только у портретов. Один счётчик внизу.

**Грабли раскладки:** блок пула сжимался в ноль (дерево `flex-grow`, блок по
умолчанию тоже сжимается) — поле «кадров» было высотой 3 px. Лечится
`flex-shrink: 0`. **И важное про верификацию: `read_console` показывал 0
ошибок, когда компиляции вообще не было** — проверять пересборку по времени
`Library/ScriptAssemblies/*.dll`, а не по пустой консоли.

EditMode **224/224** (было 216: −2 снятых теста состояния, +10 на сканер),
консоль чистая, состояние окружения восстановлено. Отчёт:
`docs/reports/2026-10-09-art-studio-review-ui-redesign-report.md`.

### Дополнение 2: нижняя панель и плитка «＋ добавить кадры»

Пользователь: блок «Пул / Сгенерировать / Доп. кадры / буквы» непонятен;
хочется помечать брак на разных объектах и перегенерировать одной общей
кнопкой; и добавлять пулу 1..N новых вариантов «плюсиком» в списке кадров.

Сделано: **внизу окна новая панель** общих действий («Перегенерировать
помеченное (N)», «Доп. места (фоны)», счётчики, проблемы); **под списком кадров
плитка «＋ Добавить кадры»** с полем количества; слева осталось только дерево
(блок «Пул» и поле «буквы» убраны); справа — только выбранный объект.

**Буквы считает окно**, а не человек: плитка спрашивает «сколько», окно берёт
следующие свободные буквы, дописывает в `extra_pools.json` и отправляет

`pool.Free`, а драйвер считает свободным всё, чего нет в проекте, — кандидат в
проект ещё не попал. Повторное «добавить» перегенерировало бы уже сделанного
кандидата. Введён `AvailableIds()` = свободные минус кандидаты.

(−7 тестов убранной валидации букв, +4 на расчёт). Состояние восстановлено.

идёт через `bee_backend` до минуты, `read_console` при этом показывает 0 ошибок.
