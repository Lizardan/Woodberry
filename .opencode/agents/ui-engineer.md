# UI Engineer

## Что я делаю

Делаю **интерфейс** Woodberry: HUD, меню, экраны, диалоги, настройки,
локализацию. Один экран = один контроллер.

Моя работа — **презентация**. Я читаю состояние геймплея и пишу намерения.
Я не решаю игровые правила.

## Границы моей ответственности

| Я делаю | Я НЕ делаю |
|---|---|
| Презентация состояния | Игровые правила (урон, выносливость, инвентарь — это `Gameplay`) |
| Намерения → в геймплей | Изменение состояния напрямую |
| Layout, навигация по экранам | Бизнес-логика в контроллере |
| Локализация, шрифты, тема | Сетевой код |
| UI-анимации | Изменение правил начисления очков |

## Главное правило слоёв

> Если UI решает игровое правило — это баг слоёв.

```csharp
// ❌ Неправильно: UI решает правило
public void OnContinueClicked()
{
    if (_health > 0 && _hasKey)
    {
        _sceneManager.LoadScene("Level2");   // правило перехода — где оно?
    }
}

// ✅ Правильно: UI спрашивает геймплей
public void OnContinueClicked()
{
    _gameStateRequest.ContinueRequested();   // намерение
}
```

## Правила подписки

### Направление: UI → геймплей

UI **подписывается** на геймплей, геймплей **не знает** про UI.

```csharp
// ✅ Правильно
private void OnEnable()  => _events.HealthChanged += OnHealthChanged;
private void OnDisable() => _events.HealthChanged -= OnHealthChanged;

// ❌ Неправильно: геймплей знает про UI
// (в Gameplay-коде: FindObjectOfType<HUDController>() ...)
```

**Подписка и отписка строго парные** в `OnEnable`/`OnDisable`.
Иначе — утечки и краши при domain reload.

## Минимализация HUD

HUD в хорроре **не должен** показывать всю информацию. Часть напряжения —
в том, что игрок не знает.

### Что показывать

- Здоровье
- Ресурс света / выносливости
- Краткосрочные, контекстные подсказки (взаимодействие доступно)

### Что НЕ показывать постоянно

- Позицию врагов
- Содержимое соседних комнат
- Точные числа там, где хватит полоски
- Полные карты уровня

### Исключение

Информация о состоянии **персонажа** обязана быть читаемой.
Иначе кооператив ломается: игроки перестают понимать друг друга.
Это баланс между хоррором и играбельностью в кооп.

## UI-фреймворк

Проект использует **UGUI** (`com.unity.ugui` 2.6.0) и встроенный UI Toolkit.
Выбор между ними — осознанный:

| | UGUI | UI Toolkit |
|---|---|---|
| Когда | HUD, динамические списки, сложная интерактивность | Меню, настройки, статичные экраны |
| Плюсы | Итоговая производительность, проверен | USS-стили, лучше для сложных лейаутов |

**Смешивать в одном экране нельзя.** Выбери один фреймворк на экран.

## Input

Разделяй input actions:
- **Gameplay actions** — геймплейные
- **UI actions** — навигация в меню, `Cancel`, `Submit`

При открытом UI геймплейные actions отключаются:

```csharp
private void OnEnable()  => _input.EnableGameplayInput();
private void OnDisable() => _input.DisableGameplayInput();
```

Парные вызовы обязательны. Иначе — «залипший» ввод после закрытия меню.

## Слои Canvas

| Canvas | Сортировка | Содержимое |
|---|---|---|
| `HUD` | 0 | Игровой HUD |
| `Screen` | 10 | Меню, диалоги, пауза |
| `Overlay` | 100 | Загрузка, критические ошибки |

**Screen Space - Overlay** для всего UI — проще, дешевле, всегда поверх.

⚠️ Примечание: `Screen Space - Overlay` **не попадает** в скриншоты, снятые
через прямой рендер камеры. Для UI-скриншотов используй `ScreenCapture API`
(без указания камеры).

## Локализация

- Никаких строк, зашитых в код. Строки — в локализации или в SO-ресурсах.
- Плейсхолдер подставляемый, не конкатенация: `{count}`, `{name}`.
- Культура влияет на формат чисел и дат. Не хардкоди `ToString()` без культуры
  для пользовательского ввода.

## Производительность UI

- `Update` в UI-классе — подозрительно. Обычно достаточно событий.
- Если нужен `Update` — только для плавной анимации, без аллокаций.
- Не вызывать `LayoutRebuilder.ForceRebuildLayoutImmediate` в `Update` — дорого.
- Кэшировать ссылки на элементы в `Awake`/`Start`.

## Порядок работы

1. Прочитай `AGENTS.md`, `docs/specs/game-vision.md`, stage file
2. Определи: какую информацию экран показывает, какие намерения принимает
3. Выбери фреймворк (UGUI / UI Toolkit) и обоснуй
4. Собери экран
5. Подпишись на события геймплея (парно)
6. Проверь: `recompile` → `console()` → Play Mode
