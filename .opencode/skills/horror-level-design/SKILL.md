# Horror Level Design

## Триггер

Используй, когда:
- собираешь новую сцену/уровень
- настраиваешь свет и пост-обработку
- уровень кажется «нечитаемым» или «нестрашным»
- настраиваешь камеру

## Главный конфликт

```
Читаемость  ←──────────→  Атмосфера
(кооператив)              (хоррор)
```

**Слишком темно** = игрок не играет. **Слишком светло** = не страшно.
Рабочий диапазон узкий. Задача сцены — найти его.

## Правило: страх через то, чего НЕ видно

| Пугает | Не пугает |
|---|---|
| Неизвестность за углом | Неожиданная смерть |
| Тьма как отсутствие информации | Gore |
| Звук как источник данных | Скримеры |
| Ограниченная видимость | Слишком тёмная «нечитаемая» картинка |
| Редкие, громкие события | Постоянный шум |

## Что должно читаться ВСЕГДА

- Положение игрока и его конус света
- Положение партнёров по команде (это критично для кооператива)
- Границы проходимого пространства
- Опасные объекты в зоне видимости

## Что МОЖЕТ быть не видно

- Что за углом
- Что вдали от источников света
- Содержимое закрытых помещений
- Что будет дальше по маршруту

## Свет: правила

### Бюджет

| Тип | Правило |
|---|---|
| Статический | **Запекать** |
| Динамический | Только движущееся (игроки, переключатели, факелы) |
| Тени | Точечно. Каждый каскад = целый проход рендера |

### Ambient

Минимальный, но **не нулевой**. Причина: иначе не различить силуэт и пустоту,
и кооперативный игрок не найдёт партнёра.

### Практика: один экран за раз

Темнота допустима, если игрок **знает, куда идти**. Источник света партнёра
может быть единственным ориентиром — это кооператив, а не баг.

## Пост-обработка (URP Volume)

| Эффект | Роль | Ошибка |
|---|---|---|
| **Vignette** | Сужает поле зрения | Слишком сильная — игрок «слепнет» по краям |
| **Bloom** | Мягкое свечение источников | Слишком сильный — засвечивает картинку |
| **Color Adjustments** | Холодные/зелёные тона | Слишком много — «грязь» вместо ужаса |
| **Film Grain** | Убирает цифровую чистоту | Слишком сильный — мешает читаемости |
| **Tonemapping** | Иначе свет плоский | Без него всё выглядит дёшево |

**Приоритет — свет, не пост-обработка.** Если сцена «серая» вместо «мрачной» —
переделай свет, а не крути saturation.

## Камера (top-down)

| Параметр | Правило | Почему |
|---|---|---|
| Угол | Фиксированный или узкий диапазон | С自由度 вращения теряется ориентация |
| Следование | Плавный lerp | Резкая привязка = укачивание |
| **Dead zone** | **Обязателен** | Без неё стоящий игрок «плавает» |
| Look-ahead | Небольшой, по направлению | Помогает видеть, куда идёшь |
| Зона видимости | Не показывать пустоту | Кадр пустоты = потерянное время |

### Frame-rate независимое сглаживание

```csharp
// ❌ Зависит от FPS
float t = 0.1f;
transform.position = Vector3.Lerp(a, b, t);

// ✅ Независимо
float k = 1f - Mathf.Exp(-smoothTime * Time.deltaTime);
transform.position = Vector3.Lerp(a, b, k);
```

## Процесс проектирования уровня

1. **Цель уровня:** что игрок должен пережить, узнать, сделать
2. **Layout:** где проходы, где тупики, где укрытия
3. **Свет:** статический запечён + динамический для ключевых точек
4. **Камера:** угол, dead zone, границы
5. **Пост-обработка:** точечно, не перебарщивая
6. **NavMesh:** запечь
7. **Проверка читаемости**

## Проверка: цикл «темнота»

```
1. Запустить Play Mode
2. ВЫКЛЮЧИТЬ весь внешний свет
3. Оставить только конус света игрока
4. Пройти уровень
```

Оцени:

| Вопрос | Провал означает |
|---|---|
| Хватает ли конуса для навигации? | Слишком темно |
| Видны ли силуэты партнёров? | Слишком темно или слишком мало динамического света |
| Понятно ли, куда идти? | Нет ориентиров — добавь ambient или ключевые световые маяки |
| Видны ли интерактивные объекты? | Нет feedback — добавь подсветку |
| Тревожно ли? | Слишком светло или нет звука |

## Проверка: 4 игрока

Обязательно, игра кооперативная:

- Свет **не должен** перекрывать обзор в куче (over-brightening)
- Камеры игроков не должны показывать чужую тьму как свою
- Синька не нужна — достаточно понимания, кто где

## Скриншоты

```
mcp__unityMCP__manage_camera(action="screenshot", include_image=true, max_resolution=800)
```

⚠️ `Screen Space - Overlay` UI **не попадает** в скриншот при указании камеры.
Для UI — без параметра `camera`.

## Критерии успеха

- [ ] Уровень проходим в темноте без потери ориентации
- [ ] Партнёры видны в зоне света
- [ ] Интерактивные объекты читаемы
- [ ] Статический свет запечён
- [ ] NavMesh запечён
- [ ] Камера не дёргается, dead zone работает
- [ ] Проверено на 4 игроках
- [ ] Скриншот приложен к отчёту
- [ ] Указано, что проверено, а что — нет
