# Unity Prefab Safety

## Триггер

Используй, когда:
- создаёшь префаб
- переименовываешь ассет
- работаешь со сценой
- видишь `Missing (Mono Script)`
- добавляешь ассеты в проект

## Три запрета, нарушение которых ломает проект

### 1. Никогда не редактируй Unity-ассеты как текст

`.unity`, `.prefab`, `.asset`, `.mat` — **только** через редактор или MCP.

Ручной YAML-редактит работает «вроде бы», а потом тихо ломает ссылки,
идентификаторы инстансов, порядок компонентов и GUID-ссылки.

```powershell
# Проверка на вредную привычку
git diff --name-only | Where-Object { $_ -match '\.(unity|prefab|asset|mat)$' }
```

Если в diff попали такие файлы — проверь, что это не ручная правка.
Легитимное изменение возможно **только** через редактор/MCP
(и тогда файл в diff — ожидаемо).

### 2. Никогда не удаляй `.meta` вручную

Отсутствующий `.meta` = все ссылки на ассет потеряны **у всей команды**.

Удалять асеты — через редактор или `AssetDatabase.DeleteAsset`.
Переименовывать — через редактор, `.meta` едет вместе с ассетом.

```powershell
# Проверка: у каждого ассета есть .meta
Get-ChildItem -Recurse Assets -File |
  Where-Object { $_.Extension -ne ".meta" -and $_.Extension -ne "" } |
  ForEach-Object {
    if (-not (Test-Path "$($_.FullName).meta")) { "MISSING META: $($_.FullName)" }
  }
```

### 3. Никогда не редактируй `.meta` вручную

GUID внутри `.meta` — это идентичность ассета. Правка руками ломает
все ссылки, которые на него указывают.

## Создание префаба

### Правильный путь

1. Создать и настроить объект(ы) в сцене
2. Выделить корневой объект
3. **GameObject → Prefab** (или Ctrl+D) → сохранить в `Assets/Woodberry/Prefabs/`
4. Переименовать в `PascalCase`
5. В инспекторе префаба: **Overrides → Apply All**
6. Удалить временный экземпляр из сцены

### Правила

| Правило | Почему |
|---|---|
| Префаб — источник правды для повторяющихся объектов | Иначе изменения придётся вносить вручную везде |
| Изменения только через `Apply` | Ручная правка инстанса ломает связь |
| Логика префаба не зависит от единственного экземпляра | Префаб может быть заспавнен N раз |
| Имя `PascalCase` | `Enemy_Zombie.prefab`, не `New Prefab (1)` |

### Проверка инстансов

```powershell
# Сколько мест дублирует один и тот же префаб
Select-String -Path "Assets/Woodberry/Scenes/*.unity" -Pattern "m_PrefabInstance" |
  Group-Object { $_.Line } | Sort-Object Count -Descending
```

Большое число одинаковых строк = настроенный дубликат вместо префаба.

## Переименование ассета

### Правильный путь

Переименование **в редакторе** (Project view → F2).

Unity обновит `.meta` и все ссылки автоматически.

### Что ломается при неправильном

| Действие | Последствие |
|---|---|
| Переименовать `.cs` вручную (без `.meta`) | `Missing Script` во всех сценах и префабах |
| Переименовать `.meta` вручную | Тот же `Missing Script`, но необратимо для git-истории |
| Переименовать `.prefab` вручную | Потеря всех ссылок на префаб |

## Сцены

### Правильный путь

manage_scene(action: "get_hierarchy", page_size: 100, max_depth: 3)
manage_asset(action: "search", path: "Assets/Woodberry/Prefabs", filter_type: "Prefab", page_size: 25)

### Обязательное содержимое

- ✅ Камера (или `CameraRig`)
- ✅ Свет (минимальный, чтобы сцена читалась)
- ✅ Для игровых уровней: `NavMeshSurface` + запечённый NavMesh
- ✅ Точка входа / spawn

### Build Settings

Сцена попадает в сборку только через **File → Build Settings → Add Open Scenes**.
Файла на диске недостаточно.

## Диагностика `Missing (Mono Script)`

### Причины

1. Скрипт удалён, компонент остался
2. Скрипт переименован, `.meta` — нет
3. Ошибка компиляции: тип не существует в сборке
4. Скрипт вне asmdef, а сцена ссылается на старую сборку

### Порядок действий

**Сначала** проверить компиляцию — это чаще всего причина:

read_console(action: "get", types: ["error"], count: 50)

Если компиляция чистая:
1. Найти объект со ссылкой (Hierarchy / Prefab Mode)
2. Открыть инспектор — поле `Script` пустое
3. Переназначить скрипт перетаскиванием
4. Если скрипт удалён намеренно — удалить компонент
5. `File → Save`

## Проверка перед коммитом

```powershell
# 1. Нет Missing-скриптов (требует открытого Unity, проверяется через MCP)

# 2. .meta на месте
git status --short
git status --short -- "*.meta"

# 3. Новые ассеты в правильных папках
git status --short -- Assets | Where-Object { $_ -notmatch "Woodberry\\|Scripts\\|Tests\\|Scenes\\|Settings\\" }

# 4. Нет мусора
git status --short | Where-Object { $_ -match "Library|Temp|Logs|obj|\.csproj|\.sln" }
```

## Критерии успеха

- Префабы — источник правды, дубликатов нет
- У всех ассетов есть `.meta`
- Нет ручных правок YAML Unity-ассетов
- `Missing Script` отсутствует
- В ответе указано, что проверено, а что — нет
