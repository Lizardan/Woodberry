# Code Review Checklist

## What I do

Provide a structured, layer-specific checklist so no critical concern is missed during
code review. Apply the sections for the layers actually touched.

Применяется на **шаге 3** review flow из `docs/specs/code-review-flow.md`.
Какая секция нужна — определяет скилл `git-diff-analysis`.

---

## Слой: `Assets/Scripts/Net/` (сетевой слой) 🔴

- [ ] **Весь сетевой код — только здесь.** Сетевые API вне `Net/` — Critical
- [ ] Клиент **не является** source of truth: нет прямой мутации игрового состояния
- [ ] Каждое действие проходит путь intent → серверная валидация → репликация результата
- [ ] Спавн сущностей — **только** на authority
- [ ] Реплицируются состояние и результаты, **не** анимации / VFX / звук / UI
- [ ] Нет `NetworkBehaviour`, наследованного в `Gameplay/`
- [ ] Local и remote игрок — **один класс**, не два
- [ ] Подписки на сетевые события отписываются в `OnDisable`
- [ ] Частота симуляции и репликации соответствует `docs/specs/coop-networking.md`
- [ ] Есть интерполяция: репликация 10–15 Hz без интерполяции = дёрганое управление
- [ ] `IsAuthority` запрашивается через `INetworkService`, а не напрямую у транспорта

## Слой: `Assets/Scripts/Core/` (композиция и абстракции) 🔴

- [ ] `Core` **не ссылается** на `Gameplay` — направление строго вниз
- [ ] Абстракции минимальны: нет методов «на будущее»
- [ ] `IInputReader` возвращает семантическое действие (`Move`), не ось устройства
- [ ] Нет строковых имён input-экшенов
- [ ] Нет `Resources.Load` для геймплейных данных
- [ ] Composition root — единственное место, собирающее зависимости вниз вверх
- [ ] Нет `FindObjectOfType` (кроме `Awake` сценового bootstrap'а)
- [ ] Нет статических синглтонов без обоснования в ADR

## Слой: `Assets/Scripts/Gameplay/` (игровые правила) 🟠

- [ ] `Gameplay` **не знает** про `UI` и **не знает** про `Net` напрямую
- [ ] Чистая логика вынесена из `MonoBehaviour`, если это возможно (тестируемость)
- [ ] `[SerializeField] private` + property, **не** `public`-поля
- [ ] Имя файла = имя типа
- [ ] Namespace соответствует папке: `Woodberry.Gameplay.<Domain>`
- [ ] Нет `GetComponent` в `Update`/`FixedUpdate`/`LateUpdate`
- [ ] Нет `new`, LINQ, строковой интерполяции в горячих путях
- [ ] `foreach` по `List<T>` без мутации внутри
- [ ] Публичные методы, меняющие состояние, возвращают `bool` / `Try`-паттерн
- [ ] Значения клампятся: ресурс не уходит в отрицательное
- [ ] Одноразовые события (например, `OnDied`) поднимаются ровно один раз
- [ ] `0` — валидное значение, а не «нет ресурса»
- [ ] Балансные числа — в SO-конфиге, а не в коде

## Слой: `Assets/Scripts/UI/` (презентация) 🟠

- [ ] **Нет игровых правил** в UI-коде — UI пишет намерения, а не правит состояние
- [ ] Подписки парные: `+=` в `OnEnable`, `-=` в `OnDisable`
- [ ] Нет зашитых строк — всё в локализации или SO-ресурсах
- [ ] Нет аллокаций в `Update`
- [ ] `IInputReader.EnableGameplayInput/DisableGameplayInput` вызываются парно
- [ ] Один экран = один контроллер
- [ ] Не смешаны UGUI и UI Toolkit в одном экране
- [ ] Один экран = один слой Canvas

## Слой: `Assets/Scripts/AI/` (поведение) 🟠

- [ ] Восприятие — через сенсорные абстракции, **не** прямой доступ к полям других сущностей
- [ ] `NavMeshAgent` используется по назначению, `RecalculatePath` вызывается при смене навигации
- [ ] Враг не застревает: есть выход из состояний, а не только вход
- [ ] Пути пересчитываются при изменении препятствий
- [ ] Нет аллокаций в `Update`/`FixedUpdate` (сенсорные проверки — в горячем пути)

## Слой: `Assets/Scripts/CameraRig/` 🟠

- [ ] Сглаживание **независимо от FPS**: `1 - exp(-k * dt)`, а не `lerp(a, b, 0.1f)`
- [ ] Есть dead zone — иначе стоящий игрок «плавает»
- [ ] Параметры камеры в SO-конфиге, не в коде
- [ ] Цель передаётся снаружи, не ищется `FindObjectOfType`

## Слой: `Assets/Scripts/Save/` 🔴

- [ ] Схема версионирована: поле `version` в корне файла
- [ ] Старый сейв открывается новым кодом либо падает с понятным сообщением
- [ ] Запись атомарна: временный файл → переименование
- [ ] Нет Unity-типов, которые не сериализуются, в DTO
- [ ] Нет секретов и персональных данных в сейве
- [ ] Сохранение в сетевой сессии запрещено

## Слой: `Assets/Scripts/Editor/` 🟡

- [ ] Весь код под `#if UNITY_EDITOR` либо в папке `Editor`
- [ ] Валидатор **сообщает** об ошибке, а не молча проходит
- [ ] Нет зависимостей Editor-кода от runtime-кода, которого не будет в player

## Слой: `*.asmdef` (границы сборок) 🔴

- [ ] `Woodberry.Editor.asmdef` → `includePlatforms: ["Editor"]`
- [ ] `Woodberry.Runtime.asmdef` **не** ссылается на `Woodberry.Editor`
- [ ] `Woodberry.Core.asmdef` не ссылается на `Woodberry.Runtime` (направление вниз)
- [ ] Нет циклических ссылок между сборками
- [ ] `Woodberry.Tests.*` ссылаются на то, что реально тестируют
- [ ] Все asmdef — валидный JSON

## Слой: Unity-ассеты (`Assets/Woodberry/`) 🔴

- [ ] `.unity` и `.prefab` изменены **не** ручным YAML-редактом
- [ ] У каждого ассета есть `.meta`, и он в том же коммите
- [ ] Ассет переименован **через редактор**, `.meta` переехал вместе с ним
- [ ] Имена — `PascalCase`, без пробелов, без кириллицы
- [ ] Игровой контент лежит в `Assets/Woodberry/`, а не разбросан по `Assets/`
- [ ] Пиксель-арт: `Filter Mode = Point`, `Mip Maps` выключены
- [ ] Текстуры > 2048 — только с обоснованием
- [ ] `Read/Write` выключен на текстурах и мешах, где он не нужен
- [ ] Один материал на много объектов, а не материал на объект
- [ ] SO-конфиги: `OnValidate` проверяет инварианты, SO неизменяем в рантайме
- [ ] Повторяющиеся объекты — префабы, а не настроенные дубликаты в сцене

## Слой: `Assets/Tests/` 🟡

- [ ] Новая логика покрыта тестом (без теста задача не завершена)
- [ ] Чистая логика — EditMode, `MonoBehaviour` — PlayMode
- [ ] Имя: `Метод_WhenУсловие_ThenОжидание`
- [ ] Один тест — одно поведение
- [ ] Проверяется **наблюдаемое поведение**, не приватные поля
- [ ] Есть ассерты (тест без ассертов — мусор)
- [ ] Покрыты краевые случаи: ноль, отрицательное, граничное, за границей, повторный вызов
- [ ] Есть **негативные** сценарии, а не только happy path
- [ ] Тесты независимы от порядка выполнения
- [ ] PlayMode-тесты чистят за собой: destroy объектов, снятие подписки
- [ ] Нет `Time.timeScale` ради ускорения без необходимости
- [ ] Нет `Assert.Ignore` / `[Ignore]` без причины в отчёте
- [ ] Нет БД, файловой системы, сети

## Слой: Документация 🟡

- [ ] `docs/specs/` обновлён, если изменился контракт, схема или сетевое правило
- [ ] `docs/stages/stage-NN-*.md` — изменение входит в объявленный scope
- [ ] `AGENTS.md` обновлён, если изменилось правило или структура
- [ ] `README.md` обновлён, если изменились шаги запуска или структура
- [ ] `docs/reports/` содержит отчёт с честными `Not verified` и статусом acceptance criteria
- [ ] ADR создан или обновлён, если решение архитектурное
- [ ] Нет `TODO` без ссылки на issue / stage / ADR
- [ ] Нет закомментированного кода
- [ ] Нет мёртвого кода

## Слой: Инфраструктура 🔴

- [ ] `Packages/manifest.json` изменён обоснованно, версия зафиксирована в `AGENTS.md`
- [ ] `ProjectSettings/ProjectVersion.txt` не изменён (если только это не задача)
- [ ] Версия Unity в проекте совпадает с `6000.6.3f1`
- [ ] Нет секретов в закоммиченных конфигах

---

## Cross-cutting (всегда)

- [ ] **Нет секретов**: `password`, `token`, `secret`, `api_key`, `apikey` в коде и конфигах
- [ ] **Нет debug-кода**: `Debug.Log` в hot path, `Console.WriteLine`, закомментированные куски
- [ ] Файлы затронуты, но не относящиеся к изменению, случайно не модифицированы
- [ ] Соглашения stage соблюдены: один stage за раз, вертикальный срез
- [ ] Логирование и обработка ошибок присутствуют на длинных и внешних путях
- [ ] Исключения не проглатываются; ошибки логируются с контекстом
- [ ] **Верификация честна** — агент не заявляет то, что не проверял

## Как обновлять этот чеклист

Обновляй при каждом новом архитектурном правиле или когда агент пропустил что-то
важное. Чеклист — живой документ, а не разовая настройка.
