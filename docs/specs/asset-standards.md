# Spec — Asset Standards

Статус: Draft

## Имена

- **Папки** — `PascalCase`. Категория — одна папка, подкатегория — вложенная.
- **Файлы ассетов** — `PascalCase`, без пробелов, без кириллицы.
- Unity генерирует `New GameObject`, `Cube` и подобные — **переименовывай сразу** при создании.

## Ордер ассетов

Весь игровой контент — в `Assets/Woodberry/`:

```
Assets/Woodberry/
├─ Art/        # спрайты, текстуры, 2D
├─ Audio/      # Music / SFX / Ambience / UI
├─ Materials/
├─ Models/
├─ Prefabs/
├─ Scenes/
├─ Settings/   # SO-конфиги уровней, баланс
├─ UI/
└─ VFX/
```

`Assets/Settings` — только URP/рендер-ассеты шаблона Unity.
Новый игровой контент туда не клади: сцены — в `Assets/Woodberry/Scenes/`,
ассеты оформления — в `Assets/Woodberry/{Art,Materials,Models,Prefabs,UI,VFX}/`.

## Сцены

| Файл | Назначение | Индекс в Build Settings |
|---|---|---|
| `Assets/Woodberry/Scenes/Bootstrap.unity` | Сборка и регистрация глобальных сервисов | 0 |
| `Assets/Woodberry/Scenes/Menu.unity` | Главное меню | 1 |
| `Assets/Woodberry/Scenes/Game.unity` | Геймплей | 2 |

Имена файлов — **без префикса `Woodberry_`**: папка `Assets/Woodberry/Scenes/`
уже задаёт контекст. Префикс в имени файла дублировал бы её.

Скриншоты и прочие артефакты проверки в `Assets/` не кладутся: они попадут
в импорт и в сборку. `manage_camera(action: "screenshot")` кладёт их в
`Assets/Screenshots/` — после проверки папку нужно удалить.

## Модели

| Параметр | Значение |
|---|---|
| Scale | `1 unit = 1 метр` |
| Forward | `+Z` |
| Up | `+Y` |
| Pivot | По центру масс / у основания для персонажей |
| Тип коллайдера | По возможности Mesh, иначе примитивы |
| Read/Write | Выключено, если не нужен `Mesh` в рантайме |
| Optimize Mesh | Включено |
| Import Normals / Tangents | Включено, если есть текстуры |
| Compression | По необходимости: Off для героев, Medium для окружения |

## Текстуры

Игра двухмерная, см. `docs/adr/0007-2d-sprite-game.md`. 3D-строки оставлены
на будущее, сейчас они не используются.

| Тип | PPU | Filter | Mipmaps | Compression |
|---|---|---|---|---|
| Персонаж (кадр 128×128 px) | **128** | Bilinear | Выкл | Uncompressed |
| Тайл пола и земли (256×256 px) | **128** | Bilinear | Выкл | Uncompressed |
| Стена (128×64 px) | **128** | Bilinear | Выкл | Uncompressed |
| Окно в стене (256×64 px) | **128** | Bilinear | Выкл | Uncompressed |
| Крона, куст, обстановка | **128** | Bilinear | Выкл | Uncompressed |
| Окружение (3D) | 1024–2048 | Bilinear | Вкл | Normal Quality |
| Нормали | 1024 | Bilinear | Вкл | NormalMap |
| Маски | 512 | Bilinear | Вкл | Normal Quality |

Правила:
- **PPU 128 у всего 2D-контента.** Раньше персонаж шёл с PPU 32, а тайлы
  с PPU 128. Расхождение было нужно, чтобы тайл 256 px не занимал 8 юнитов.
  Теперь кадр персонажа — 128×128 px, то есть при PPU 128 ровно один юнит,
  и мировой масштаб фигуры сохранился: PPU один на всё, размер задаётся
  размером кадра, а не пиксельной плотностью.
- **`Bilinear`, а не `Point`.** Арт не пиксельный: он рисуется с
  суперсэмплингом и антиалиасингом. `Point` на нём даёт рваные кромки.
  Исключение появится, если в проект придёт настоящий пиксель-арт.
- **`Mesh Type = Full Rect` у всего, что тайлится**, иначе `drawMode = Tiled`
  строит сетку по контуру непрозрачных пикселей.
- **Тайлы обязаны быть бесшовными.** Проверка: сравнить перепад на стыке
  с типичным перепадом между соседними пикселями внутри тайла. Отношение
  порядка единицы — бесшовно; заметно больше — на полу видна сетка.
  У пола стык может совпадать со швом досок: тогда отношение большое
  законно, потому что шов есть и внутри тайла.
- **Тайл пола обязан быть бесшовным** по обеим осям. Проверяется сравнением
  разрыва на стыке с разрывом между соседними пикселями: если стык заметно
  грубее, текстура не тайлится.
- **Тайлинг через `SpriteRenderer.drawMode = Tiled` требует
  `Mesh Type = Full Rect`.** С дефолтным `Tight` сетка строится по контуру
  непрозрачных пикселей и получается неверной. Свойство живёт в
  `TextureImporterSettings.spriteMeshType`, а не на самом импортёре.
- Для тайлинга `wrapMode = Repeat`.
- Текстуры > 2048 по дефолту запрещены. Нужна отдельная задача и обоснование.

## Звук

- Папки: `Audio/Music`, `Audio/SFX`, `Audio/Ambience`, `Audio/UI`.
- 3D-звук для источников в мире, 2D для UI и музыки.
- `spatialBlend` осмысленно: UI = 0, ambience = 1, SFX — по расстоянию слышимости.
- Сжатие: Vorbis для длинной музыки/ambience, ADPCM или PCM для коротких SFX.
- Load-in-background для длинных треков, preload для коротких.

## Префабы

- Префаб — **единственный источник правды** для повторяющихся объектов.
  Настройка дубликата в сцене вместо префаба — антипаттерн.
- Изменения — только через `Apply` / `Revert`. Ручное редактирование инстанса ломает связь.
- Префаб не содержит логики, зависящей от единственного экземпляра.

## Материалы и шейдеры

- Шейдер — из установленных пакетов. **Перед созданием нового шейдера** проверь,
  есть ли уже подходящий (`manage_asset(action: "search", filter_type: "Shader")`).
- Свои шейдеры и материалы — в `Assets/Woodberry/Materials/`, с префиксом
  `Woodberry/` в имени шейдера. Сейчас их два и оба про обзор:
  `Woodberry/VisionMask` и `Woodberry/VisibilityOverlay`.
- **Материал, которому в рантайме меняют свойства, обязан быть экземпляром.**
  Правка общего материала пачкает ассет в редакторе и делит состояние между
  всеми пользователями материала.
- URP: не используй старые `Standard`/`Unlit/Texture`-шейдеры, если есть URP-эквивалент.
- Один материал — много объектов. `MaterialPropertyBlock` для вариаций, а не копия материала.

## `.meta` файлы

- **Коммитятся всегда.** Отсутствующий `.meta` = битые ссылки у всей команды.
- Не удаляй `.meta` вручную при удалении ассета — удаляй через Unity.
- Не переименовывай `.meta` вручную при переименовании ассета.

## Исходники

Не коммить `.psd`, `.blend`, `.fbx` исходники, если есть экспортированная версия.
Исходники — в отдельной папке с понятным правилом, либо в git-lfs.
