# Spec — Save System

Статус: Draft
Связано: `../adr/0002-save-data-format.md`, `../adr/0011-character-and-world-saves.md`

## Две области сохранения

Разделение областей — решение `../adr/0011-character-and-world-saves.md`.
Здесь — контракт для кода.

| Область | Чей | Что внутри |
|---|---|---|
| **Персонаж** | игрока | Тело, навыки, экипировка, инвентарь, кошелёк, личный сундук |
| **Мир** | хозяина сессии | Город, повозка и модули, репутация, доска заявок, постройки |

Правило: **что едет с игроком — в персонаже; что стоит на месте — в мире.**

Не сохраняется: настройки (отдельный файл), сессия (живёт только в рантайме).

## Формат

- JSON для читаемости и diff'а при версионировании.
- Сериализация **вручную**, через DTO-классы. Не полагайся на `JsonUtility` для
  полиморфных или вложенных структур — он хрупок и не даёт версионирования.
- Путь: `Application.persistentDataPath` (на всех платформах корректный).
  Не хардкодить.
- Имена файлов: `character_{id}.json` и `world_{id}.json`.
- Два файла версионируются **независимо**, но обязаны быть совместимы друг с
  другом: персонаж гостя приходит в чужой мир.

## Версионирование

Обязательное поле `version` в корне каждого файла.

Правило: **старый сейв открывается новым кодом через миграцию.** При загрузке
код читает `version`, прогоняет цепочку `v1 → v2 → …` и только потом отдаёт
данные игре. Отказать игроку в загрузке — нельзя: сейв это десятки часов игры.

Следствие: каждая смена схемы обязана оставлять шаг миграции и тест на него.
Молчаливое игнорирование неизвестных полей запрещено.

Персонаж:

```
{
  "version": 1,
  "savedAtUtc": "2026-10-06T12:00:00Z",
  "characterId": "...",
  "skills": { ... },
  "equipment": { ... },
  "inventory": [ ... ],
  "purse": 0,
  "chest": [ ... ]
}
```

Мир:

```
{
  "version": 1,
  "savedAtUtc": "2026-10-06T12:00:00Z",
  "worldSeed": 12345,
  "cart": { ... },
  "reputation": 0,
  "guildBoard": [ ... ],
  "buildings": { ... }
}
```

## Границы

- **Сессия не сохраняется.** Активная сессия, кто подключён, состояние миссии —
  рантайм. Прерванная миссия начинается заново.
- **Персонаж переносится между мирами.** При входе в чужую сессию клиент отдаёт
  снимок персонажа авторитету, при выходе забирает итог. Это **не** сохранение
  сессии, а перенос персонажа — разные вещи, и путать их нельзя.
- Частичное сохранение (записали, упали) должно быть безопасно: пишем во
  временный файл, потом атомарно переименовываем.
- Никаких секретов и персональных данных в сейве.

## Открытые вопросы

- [x] Слоты — решено: **несколько слотов**, не одно автосохранение.
- [x] Расхождение версий — решено: гость с версией ниже в сессию не пускается,
  см. `../adr/0011-character-and-world-saves.md`.
- [x] Политика миграций — решено: **мигрируем автоматически**, цепочкой
  `v1 → v2 → …` при загрузке; отказ в загрузке запрещён.
