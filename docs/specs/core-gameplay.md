# Spec — Core Gameplay

Статус: Draft

## Базовые сущности

| Сущность | Ответственность | Где живёт |
|---|---|---|
| Игрок | Передвижение, взаимодействие, здоровье, экипировка | `Assets/Scripts/Gameplay/Player/` |
| Предмет | Определение данных (дизайн) | `Assets/Scripts/Gameplay/Items/` + SO |
| Интерактивный объект | Точка взаимодействия в мире | `Assets/Scripts/Gameplay/Interaction/` |
| Враг | Состояния, восприятие, поведение | `Assets/Scripts/Gameplay/Enemies/` + `AI/` |

## Правила

Эти правила — контракт. Нарушение = `contract drift`, ловится на review.

### Сцены и переходы

Приложение состоит из трёх сцен, см. `docs/adr/0006-scene-architecture-and-service-registry.md`.

| Сцена | Назначение |
|---|---|
| `Bootstrap` | Создаёт и регистрирует глобальные сервисы, персистит, уводит в меню |
| `Menu` | Главное меню, единственная точка входа в игру |
| `Game` | Геймплей: игрок, камера, уровень |

Правила переходов:

- В каждый момент активна **ровно одна** сцена. Переход — `LoadSceneMode.Single`.
  Меню не висит под игрой: иначе по нему можно ходить.
- Переход — это **намерение**, а не прямой вызов `SceneManager`. UI и геймплей
  знают только `ISceneLoader` из `Core`.
- `GameBootstrap` переживает переходы через `DontDestroyOnLoad`. Всё, что
  переживает смену сцены, регистрируется в `ServiceRegistry`; пишет в реестр
  **только** composition root.
- **Сериализованные ссылки между сценами не работают** — Unity обнуляет их
  при сохранении. Кросс-сценовые зависимости только через реестр.
- Сервисы собираются в `Awake`, а не восстанавливаются: `DontDestroyOnLoad`
  не сериализуется и не переживает перезагрузку домена.

### Передвижение
- Вид сверху, движение по мировым оси XZ.
- Скорость — свойство, а не константа. Значение по умолчанию задаётся в SO-конфиге.
- Правило движения обязано быть тестируемым без сцены и без `MonoBehaviour`:
  чистая функция, EditMode-тесты без Play Mode. Это готовит перенос на
  фиксированный сетевой тик из `coop-networking.md`.
- Никакой физики твёрдых тел для движения игрока. Игрок — кинематический,
  коллизия решается через `CharacterController` или собственный sweep.
  Причина: физика твёрдых тел в top-down кооперативе даёт дребезг и рассинхрон.
- Бег тратит ресурс выносливости. Ходьба — бесплатна и медленная.

### Взаимодействие
- Взаимодействие — **намерение**, а не мгновенный эффект. Клиент отправляет intent,
  авторитет валидирует и результат реплицируется. См. `coop-networking.md`.
- Радиус взаимодействия — параметр, не константа.
- Обязателен визуальный feedback: подсветка интерактивного объекта в зоне досягаемости.
  Без неё кооперативные игроки не понимают, что партнёр что-то делает.

### Ресурсы
Минимальный набор на старте: **здоровье**, **выносливость**, **источник света**.

Правила:
- Любой ресурс, который влияет на выживание, реплицируется.
- Любой ресурс, который не влияет на выживание (косметика), не реплицируется.
- `0` — валидное значение. Не используй `-1` как «нет ресурса».

### Здоровье и смерть
- Урон — единственный путь уменьшения здоровья. Регенерация — отдельное явление, если есть.
- Смерть обрабатывается один раз: `OnDied` поднимается ровно один раз за жизнь сущности.
- После смерти поведение player-specific должно быть определено (респавн, spectate, downed-состояние)
  и зафиксировано в spec, а не оставлено на волю реализации.

## Что НЕ задано этим документом

- Конкретные числовые балансные значения → `SO`-конфиги, настраиваемые дизайнером
- Конкретные предметы и их эффекты → будущие stage files
- Enemy AI → отдельная спека, ещё не написана. Планируется в stage, который разбивает
  поведение врагов. До этого момента — общие правила восприятия в `AGENTS.md → Layer AI`
