| Сущность | Ответственность | Где живёт |

## Правила

Эти правила — контракт. Нарушение = `contract drift`, ловится на review.

### Сцены и переходы

Приложение состоит из трёх сцен, см. `docs/adr/0006-scene-architecture-and-service-registry.md`.

| Сцена | Назначение |
|---|---|
| `Bootstrap` | Создаёт и регистрирует глобальные сервисы, персистит, уводит в меню |
| `Menu` | Главное меню, единственная точка входа в игру |
| `Game` | Геймплей: игрок, камера, уровень |

Правила переходов:

- В каждый момент активна **ровно одна** сцена. Переход — `LoadSceneMode.Single`.
  Меню не висит под игрой: иначе по нему можно ходить.
- Переход — это **намерение**, а не прямой вызов `SceneManager`. UI и геймплей
  знают только `ISceneLoader` из `Core`.
- `GameBootstrap` переживает переходы через `DontDestroyOnLoad`. Всё, что
  переживает смену сцены, регистрируется в `ServiceRegistry`; пишет в реестр
  **только** composition root.
- **Сериализованные ссылки между сценами не работают** — Unity обнуляет их
  при сохранении. Кросс-сценовые зависимости только через реестр.
- Сервисы собираются в `Awake`, а не восстанавливаются: `DontDestroyOnLoad`
  не сериализуется и не переживает перезагрузку домена.

### Передвижение
- **Игра двухмерная.** Вид сверху, движение в плоскости XY, рендер — спрайты
  через `SpriteRenderer`. Ортографическая камера строго вниз.
- Скорость — свойство, а не константа. Значение по умолчанию задаётся в SO-конфиге.
- Правило движения обязано быть тестируемым без сцены и без `MonoBehaviour`:
  чистая функция, EditMode-тесты без Play Mode. Это готовит перенос на
  фиксированный сетевой тик из `coop-networking.md`.
- Игрок — **кинематический** `Rigidbody2D` с `gravityScale = 0`, перемещение
  через `MovePosition` в `FixedUpdate`. Динамическое тело запрещено: в top-down
  кооперативе оно даёт дребезг и рассинхрон.
- Коллизия — `Collider2D` на игроке и `TilemapCollider2D` на окружении.
  Собственный sweep не используется.
- Движение в `FixedUpdate` совпадает с сетевым тиком 20–30 Гц из
  `coop-networking.md`, поэтому перенос на сеть не потребует переписывать цикл.
- Анимация привязана к состоянию движения, а не к кадрам: контроллер выставляет
  параметр `IsMoving`. Цикл ходьбы обязан быть зациклен (`loopTime`), иначе
  персонаж замирает на середине шага.

### Окружение
- Пол и стены — `Tilemap` с `Rule Tiles` (пакет `com.unity.2d.tilemap.extras`).
  Один тайл красится по сетке, а не расставляется руками.
- Тайлящиеся текстуры обязаны быть **бесшовными** по обеим осям, иначе на
  полу видно сетку швов. Тайлинг через `SpriteRenderer.drawMode = Tiled`
  требует `Mesh Type = Full Rect`; с дефолтным `Tight` тайлинг строится по
  контуру непрозрачных пикселей и получается неверным.
- Текстуры пола: PPU 128 для 256px тайла, `Point`-фильтр, без мипмапов,
  `wrapMode = Repeat`. Персонаж использует PPU 32; расхождение обязательно,
  иначе тайл пола не совпадёт по масштабу со спрайтом.
- Бег тратит ресурс выносливости. Ходьба — бесплатна и медленная.

### Обзор
Это контракт хоррора, а не оформление. Реализация — `Assets/Scripts/Gameplay/Perception/`,
решение и цена — `docs/adr/0008-visibility-and-darkness.md`.

- **Персонаж не видит то, что за стенами.** Обзор режется коллайдерами
  слоя `Occluder`: луч упирается в препятствие, и форма обзора обрезается
  по нему. Это следствие физики, а не проверки в коде.
- **Проём — это дырка в геометрии, а не источник обзора.** Окно и дверь
  работают одинаково: обзор проходит через них той же круговой логикой,
  что и всюду. Отдельной логики у окна нет и быть не должно.
- **Окно не лежит на слое `Occluder`.** Оно не пропускает игрока (обычный
  коллайдер), но пропускает обзор.
- **Проём в стене совпадает с нарисованным стеклом.** Если дырка в стене
  шире стекла, обзор уходит сквозь «дерево» стены по краям окна, и видимая
  область снаружи шире самого окна. Поэтому стена заканчивается по краям
  стекла, а не по краям тайла окна.
- **Снаружи видно только подойдя к окну.** Это следствие радиуса обзора,
  а не отдельного правила: издалека круг обзора до окна не достаёт.
- **Непрозрачность темноты — параметр.** Полная единица делает игру
  нечитаемой; значение задаётся так, чтобы силуэты оставались различимы.
- **Один источник обзора не влияет на другой.** Их области складываются;
  конфликтов между окнами сейчас не разрешается.
- **Кромка обзора не ступенька.** Маска гаснет в темноту градиентом:
  дальнее кольцо меша чёрное, внутреннее белое, между ними цвет
  интерполируется. Резкая граница читается как баг, а не как тьма.
- **Кромка не дрожит при движении.** Лучи добавляются по настоящим углам
  коллайдеров препятствий (углы бокса, точки касания круга), а не по сетке
  веера. Сетка веера одна не прибивает тень к геометрии: при движении угол
  попадания перескакивает с луча на луч, и граница «плавает».
- **Обзор не является освещением.** Видимая область не светлеет — она
  перестаёт затемняться. Направленный свет — отдельный слой, ещё не сделан.

### Взаимодействие
- Взаимодействие — **намерение**, а не мгновенный эффект. Клиент отправляет intent,
  авторитет валидирует и результат реплицируется. См. `coop-networking.md`.
- Радиус взаимодействия — параметр, не константа.
- Обязателен визуальный feedback: подсветка интерактивного объекта в зоне досягаемости.
  Без неё кооперативные игроки не понимают, что партнёр что-то делает.

### Ресурсы

Минимальный набор: **здоровье**, **рассудок**, **выносливость**, **свет**.
Полный список — `../gdd/02-player.md`.

Правила:
- Любой ресурс, который влияет на выживание, реплицируется.
- Любой ресурс, который не влияет на выживание (косметика), не реплицируется.
- `0` — валидное значение. Не используй `-1` как «нет ресурса».
- **Рассудок** — личный ресурс, плата за оккультное. Не реплицируется.
  См. `../gdd/02-player.md`.
- **Свет** — личный ресурс, гаснет без запаса. Реплицируется (влияет на
  видимость всех игроков).
- **Репутация** — общий ресурс сессии. Реплицируется. См.
  `../adr/0011-character-and-world-saves.md`.

### Здоровье и смерть
- Урон — единственный путь уменьшения здоровья. Регенерация — отдельное явление, если есть.
- Смерть обрабатывается один раз: `OnDied` поднимается ровно один раз за жизнь сущности.
- После смерти поведение player-specific должно быть определено (респавн, spectate, downed-состояние)
  и зафиксировано в spec, а не оставлено на волю реализации.
