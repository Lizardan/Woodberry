# Specs

Здесь лежат **durable спецификации** — то, что код сам по себе выразить не может: игровой intent, контракты, authority-модель, бюджеты.

## Что сюда относится

- Правила игры, которые должен соблюдать и дизайнер, и программист
- Сетевые контракты: что авторитетно, что реплицируется, с какой частотой
- Схема данных и сохранений
- Бюджеты производительности
- Форматы ассетов и соглашения по именованию

## Чего здесь не должно быть

- Пошаговых инструкций «как запустить» — это `docs/runbooks/`
- Обоснований архитектурных решений — это `docs/adr/`
- Описаний конкретного этапа работы — это `docs/stages/`
- Истории «что уже сделали» — это `docs/reports/`

## Список спецификаций

| Файл | О чём |
|---|---|
| `game-vision.md` | Что такое Woodberry, для кого, ядро петли геймплея и атмосферы |
| `core-gameplay.md` | Базовые игровые правила: движение, взаимодействие, ресурсы |
| `coop-networking.md` | Authority-модель, что реплицируется, тики, спавн, join/leave |
| `save-system.md` | Что сохраняется, формат, версионирование, миграции |
| `performance-budget.md` | Целевые FPS, память, draw calls, размер билда |
| `asset-standards.md` | Имена, пайплайн импорта, масштабы, оси, pivot |

## Правило обновления

Обновляй spec **до** изменения кода, если задача меняет контракт. Не нужен spec для локального бага, который не трогает intent.
