## Деревня: что генерируется

Деревня должна быть **узнаваемой, но не повторяемой**. Значит есть жёсткий
каркас и вариативная начинка.

### Обязательный каркас

- **Дома жителей** — по числу жителей, разные планировки.
- **Дом главы деревни** — старший житель, через него идёт часть показаний.
- **Выезд** — откуда приехали и куда уходят.
- **Площадь / колодец** — точка сбора и слухов.

### Опциональные особые объекты

Каталог расширяемый: часть объектов есть в деревне, часть — нет.
Наличие объекта меняет доступные улики и методы расследования.

| Объект | Зачем генерируется |
|---|---|
| Церковь / часовня | показания служителя, обряды, проверка святым |
| Кладбище | свежие могилы, нежить, ритуалы |
| Мельница | изоляция, следы, тайные встречи |
| Кузница | следы оружия, инструменты, доступ к железу |
| Таверна | слухи, пьяные показания, ночные сборища |
| Колодец / источник | отравление, чума, водные улики |
| Лесопилка / лес | твари, следы, пропажи |
| Шахта / пещера | культ, укрытие, пропавшие |
| Дом знахарки | травы, алхимия, подозрения в ведьме |
| Амбар | укрытие, следы, тела |
| Мост / река | путь, тела, засада |
| Поле / мельничный луг | знаки, проклятие, неурожай |
| Дом старосты культа | логово, вербовка |
| Башня / руины | проклятие места, старые записи |
| Скотный двор | массовый падёж — признак чумы |
| Родовой дом | старая история, документы |

### Жители деревни

- Процедурно генерируются: имена, роли, дома, расписания, отношения.
- Внешность генерируется для каждой деревни: лицо, возраст, телосложение,
  одежда, шрамы. В городе NPC **статичны** и авторские.
- Среди них — носитель угрозы, пособники и ложные следы.
- Жители **ходят по деревне** и реагируют на охотников.
- Диалог с жителем открывается в режиме визуальной новеллы: портрет на
  экране и текст с вариантами ответа. См. `07-art-audio-ux.md`.

## Роли жителей

Роль — не ярлык, а **источник лица**: от роли зависит, из какого пула берётся
портрет. Поэтому список ролей — часть контракта, а не украшение.

Правило: **чем больше ролей, тем меньше деревня похожа на деревню.** Если
кроме «жителя» ролей нет, все деревни выглядят одинаково — одни и те же
разговоры с одними и теми же людьми.

### Роли при зданиях

**Есть здание — есть роль.** Деревня без церкви не получает священника, без
кузницы — кузнеца. Это и есть механизм, которым деревня отличается от деревни:
не список ролей, а то, что в ней построено.

| Здание | Роли |
|---|---|
| Дом главы деревни | Староста |
| Церковь / часовня | Священник, Служка, Монах |
| Кладбище | Могильщик |
| Мельница | Мельник |
| Кузница | Кузнец, Подмастерье |
| Таверна | Трактирщик, Служанка, Повар |
| Лесопилка / лес | Лесоруб, Охотник |
| Шахта / пещера | Шахтёр |
| Дом знахарки | Знахарка, Травница, Повитуха |
| Мост / река | Перевозчик, Рыбак |
| Поле | Пастух, Крестьянин |
| Скотный двор | Скотник |
| Башня / руины | Отшельник |
| Амбар | — укрытие, роли нет |
| Колодец | — точка сбора, роли нет |

### Странники

Не привязаны к зданиям и появляются в деревне независимо: тянутся к таверне,
площади и дороге. Именно они не дают деревне выглядеть набором местных.

| Роль | Пол | Где встречается |
|---|---|---|
| Рыцарь | мужской | таверна, дорога |
| Наёмник | мужской | таверна |
| Паломник | любой | дорога, церковь |
| Коробейник | мужской | дорога, площадь |
| Менестрель | мужской | таверна |
| Нищий | любой | площадь, церковь |
| Прокажённый | любой | околица |
| Чумной лекарь | любой | дорога, околица, чумная деревня |

> **Повитуха и чумной лекарь добавлены 2026-10-08** — под портреты, которые
> уже нарисованы, но роли в каталоге не имели. Повитуха стоит при доме
> знахарки, потому что это одна семья ролей, а не отдельная постройка.
> Чумной лекарь — странник: он приходит в деревню, где чума уже есть, и
> одним своим появлением говорит жителям больше, чем они хотят знать.

> **Зачем это нужно.** Без странников таверна всегда будет «трактирщик плюс
> житель». Со странниками она может оказаться «рыцарь и житель» — и уже одно
> это делает деревню другой.

### Ремесленники

Необязательная прослойка: у деревни может быть мастерская, и тогда появляется
одно из ремёсел. Отдельная ось разнообразия — и отдельная причина зайти в дом.

Гончар, Ткач, Кожевник, Плотник, Пекарь, Бондарь.

### Скрытые роли

**Угроза — не отдельная роль, а скрытая надстройка.** Носитель угрозы выглядит
и ведёт себя как обычная роль: священник, мельник, житель. Именно поэтому его
и надо вычислять, а не находить.

- **Облик** — монстр принимает облик уже существующего жителя.
- **Культист** — житель, тайно служащий угрозе.
- **Пособник** — знает и покрывает.

Правило: скрытая роль **не добавляет жителя**, а накладывается на
существующего. Иначе деревня выдаст угрозу лишним человеком — а это уже не
детектив, а пересчёт.

## Тайминги

- Срок миссии — в днях, **зависит от сложности заявки и условий деревни**;
  фиксированного числа нет.
- День делится на **четыре фазы**: утро, день, вечер, ночь. **Фаза идёт по
  таймеру** — время вышло, фаза сменилась. См. `01-core-loop.md`.
- Жители имеют расписания по фазам: где кого искать в какое время. **Это и есть
  механика опроса** — жителя надо застать там, где он бывает, а не там, где
  удобно охотнику.
- Ночь — угроза активна. **Сколько жителей она забирает, зависит от угрозы**:
  её силы и того, как давно о ней знают.

## Инструменты генерации

- **Вручную — каркас:** правила, типы комнат и объектов, шаблоны сцен.
- **Процедурно — детали:** планировка, жители, угроза, улики, расписания.
- Генерация обязана быть **детерминированной по seed**: одна заявка = одна и
  та же деревня для всех игроков и при повторной загрузке.
- У деревни должна быть **одна разгадываемая истина**, а не набор случайностей.

### Планировка — модульная сборка

Деревня **не генерируется свободно**. Она собирается из готовых кусков по
правилам: есть дом, мельница, площадь — и между ними прокладываются связи.

Почему так, а не свободная генерация: свободная даёт больше разнообразия, но
регулярно выдаёт деревни с тупиками, оторванными домами и непроходимыми
местами. Ловить это тестами дороже, чем собирать из кусков, которые уже
проверены.

Разнообразие при этом не теряется — оно идёт от **набора и сочетания** кусков,
а не от случайной геометрии. Десятая деревня будет другой, потому что в ней
другая мельница, другой колодец и другие жители, а не потому что дома встали
под случайным углом.

Seed и воспроизводимость увязать со `../specs/save-system.md`.

| Торговец | снаряжение, расходники, алхимия |
| Кузница | улучшение оружия и брони |
| Алхимик | рецепты, ингредиенты, зелья |

Город — большая локация, по которой можно бегать; друг может зайти и
появиться рядом. См. `01-core-loop.md`.

## Повозка

Повозка стоит на дороге у выезда из города: в неё садятся и отправляются на
миссию. Это **общий для всех игроков в сессии** объект, и он **принадлежит
миру**, а не персонажу — гость не увозит её домой, см.
`../adr/0011-character-and-world-saves.md`.

Что она даёт:

- **Походный сундук 4×4** — запас на миссию, доступен у повозки.
- **Лазарет** — здесь приходит в себя тяжело раненый, см. `02-player.md`.
- **Модули**, которые открываются по мере улучшения: алхимическая лаборатория,
  стойка для оружия, клетки, скрытый отсек, кухня, укрепление бортов.

Правила:

- Улучшается в городе за деньги и репутацию; прокачка **линейная**, каждый
  уровень открывает один модуль, у части есть условие — особый предмет или
  особое задание.
- **Модули видно на самой повозке.** Она стоит в городе как реальный объект,
  к которому можно подойти, и по виду понятно, чего добился отряд. Это общая
  награда — значит, и видеть её должны все.
- **Дорога — пока просто переход** между городом и деревней. Случайные события
  в пути — возможное расширение, не сейчас.

> **Порядок работы: сначала каталог модулей, потом уровни.** Сперва расписать
> всё, что повозка может дать и как это меняет миссию, — и только из этого
> каталога выводить число уровней. Иначе выйдет наоборот: уровни есть, а
> наполнять их нечем. См. `99-open-questions.md`.

## Пейсинг миссии

```
Приезд (спокойствие) → первые улики (нарастание) → первая ночь (давление)
→ ложный след (сомнение) → вторая ночь (потери) → разгадка (решение)
→ приговор (кульминация) → исход
```

Правило: **тишина важнее скримера**. Опасность нарастает через потери и
нехватку информации, а не через постоянный шум.
