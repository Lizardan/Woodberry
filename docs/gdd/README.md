# GDD — Woodberry

Статус: Draft
Обновлено: 2026-10-06

## Что это

Единый источник замысла игры: что это за игра, зачем она такая, как устроены её
петли, системы, мир и рамки. Документ рассчитан на двух читателей сразу —
человека и AI-агента. Структура, термины и решения описаны явно, чтобы агент,
прочитав `AGENTS.md` и GDD, сразу понимал проект и мог брать задачи.

## Правило связей

GDD отвечает на вопрос «что и зачем». Он не дублирует другие слои документации.

| Слой | Вопрос | Где |
|---|---|---|
| GDD | Что это за игра и зачем | `docs/gdd/` |
| specs | Обязывающий контракт для кода | `docs/specs/` |
| adr | Почему выбрана технология | `docs/adr/` |
| stages | Единица работы «сейчас» | `docs/stages/` |
| reports | Что реально сделано | `docs/reports/` |

Правила:

- Если факт уже описан в spec — GDD **ссылается** на него, а не копирует.
- Если GDD меняет игровой контракт — сначала обновляется spec, потом код.
- Каждое решение, влияющее на несколько систем, фиксируется в
  `99-open-questions.md` (журнал решений).
- Изменение GDD — до кода, не после.

## Как читать агенту

1. `AGENTS.md` — технический контракт проекта.
2. `docs/gdd/00-vision.md` — что за игра.
3. `docs/gdd/01-core-loop.md` — что делает игрок и как выглядит сессия.
4. Профильный файл GDD по теме задачи.
5. `docs/stages/` — рамка текущего этапа.

## Глоссарий

| Термин | Значение |
|---|---|
| Охотник | Игровой персонаж, член ордена инквизиции |
| Орден | Инквизиция; выдаёт заявки, платит, карает за провалы |
| Заявка | Контракт гильдии на деревню; выбирается в городе |
| Деревня | Миссия: локация с жителями и скрытой угрозой |
| Угроза | То, что губит деревню: монстр, культ, чума и т.п. |
| Приговор | Финальный акт миссии: указать на жителя и казнить |
| Репутация | Отношение ордена к охотнику; падает за провалы |
| Карета | Точка выезда из города на миссию |
| Особый предмет | Инструмент на миссию; берётся 4 штуки из города |

## Что НЕ входит в GDD

- Технические решения — `docs/adr/`
- Формат данных и сейвов — `docs/specs/save-system.md`
- Пошаговые инструкции — `docs/runbooks/`
- Рамка текущей работы — `docs/stages/`
