# Stage 02 — Light and Visibility

Статус: **Не начат**
Зависит от: Stage 01

## Goal

Игрок несёт источник света, освещает участок вокруг себя, и всё остальное погружено в темноту. В темноте не видно, но слышно.

## Business value

Это ядро хоррора. Видимость становится **ресурсом**: её надо тратить, экономить и о ней надо думать. Одновременно это первая механика, которая делает кооператив интересным — свет одного игрока освещает зону другого.

## Scope

- Источник света на игроке: интенсивность, радиус, батарея
- Паттерн источников света в мире (статические, ограниченные по времени)
- Затухание света по расстоянию
- Энергозатраты фонаря, разряд батареи
- Визуальный слой темноты: URP Volume (Vignette, Bloom, Color Adjustments, Film Grain)
- **Звуковое восприятие** — базовая заглушка: игрок слышит опасность в темноте
- Свет как дизайн-инструмент: читаемость силуэтов, контраст
- PlayMode-тест: свет гаснет при нуле батареи

## Out of scope

- Сеть и репликация света
- Враги
- Предметы, кроме фонаря
- Дверь/рычаг/интерактивные объекты
- Погода, туман
- Реалистичное затухание (ray-marched shadows)
- Рефракция, каустики

## Work

### Gameplay
- `LightSource` — чистая логика: интенсивность, радиус, потребление, состояние
- EditMode-тестируемая, без зависимости от Unity-типов в логике

### Rendering
- URP Volume Profile для пост-обработки
- Настройка освещения: минимальный ambient, запечённый свет где возможно
- Layers для разделения света

### Audio
- Заглушка: зоны звукового восприятия, темнота = меньше информации

## Acceptance criteria

- [ ] Игрок имеет видимый источник света
- [ ] За пределами радиуса — темнота
- [ ] Батарея расходуется, свет тускнеет, затем гаснет
- [ ] В темноте остаётся слышно (базовый слой)
- [ ] Включённые VFX пост-обработки дают ощущение мрачности
- [ ] Игрок не «слепнет» в полной темноте — есть минимальная читаемость силуэта
- [ ] EditMode-тесты покрывают потребление и переход в состояние «разряжен»
- [ ] PlayMode-тест подтверждает: свет гаснет при нуле батареи

## Required tests

- **EditMode:** `LightSourceTests` — расход, падение интенсивности, состояния, клампы
- **PlayMode:** визуальная проверка перехода в темноту (можно через проверку `Light.enabled`)

## Risks

- **Читаемость vs атмосфера.** Слишком темно = неиграбельно, слишком светло = не страшно. Это главный риск stage. Митигация: тестировать на реальном скриншоте, а не «на глаз в редакторе».
- URP post-processing на разных GPU ведёт себя по-разному.
- Динамический свет дорогой. Ограничить количество источников.

## Dependencies

- Stage 01 (камера, движение)
- URP настроен и работает

## Deliverables

- Работающая механика света
- Настроенная мрачная пост-обработка
- Тесты
- Скриншоты для ручного QA
- Stage report
