# Runbooks

Здесь — **operational инструкции**: как запустить, как собрать, как починить.

## Отличие от остальной документации

| Документ | Отвечает на вопрос |
|---|---|
| `docs/specs/` | «Что должно быть» |
| `docs/stages/` | «Что собираемся делать» |
| `docs/adr/` | «Почему так» |
| `docs/runbooks/` | «Как это сделать руками» |

Runbook отвечает на вопрос: **«Что мне делать шаг за шагом в конкретной ситуации?»**

## Список

| Файл | О чём |
|---|---|
| `local-development.md` | Как открыть проект, настроить, запустить |
| `unity-automation.md` | Как работать с Unity через MCP |
| `test-workflow.md` | Как запускать и писать тесты |
| `build-and-release.md` | Как собрать player |
| `adding-content.md` | Как добавить новый ассет/префаб/скрипт по правилам проекта |
| `git-workflow.md` | Как коммитить в этом проекте |
| `incident-compile-errors.md` | Что делать при ошибках компиляции |

## Правило хорошего runbook

- Пронумерованные шаги
- Проверка успеха после каждого шага, а не только в конце
- Раздел «Типичные проблемы» с решением
- Явно: чего делать **нельзя**

## Правило актуальности

**Runbook, который врёт, хуже, чем его отсутствие.** Если инструкция перестала работать —
исправь в том же коммите, который сломал её. Устаревший runbook удаляй, а не оставляй «на всякий случай».
