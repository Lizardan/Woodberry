# Runbook — Git Workflow

## Purpose

Коммитить изменения в этом проекте так, чтобы история оставалась полезной,
а у всех в команде были рабочие `.meta`-файлы.

## Политика проекта

| Действие | Разрешено | Как |
|---|---|---|
| `git status` | ✅ | — |
| `git diff` / `git log` | ✅ | — |
| `git add` | ⚠️ | Только по явной просьбе |
| `git commit` | ⚠️ | **Только по явной просьбе пользователя** |
| `git push` | ❌ | Запрещено политикой (`opencode.json`) |
| `git reset --hard` | ❌ | Запрещено |
| `git clean` | ❌ | Запрещено |
| `git checkout .` | ❌ | Запрещено |

Агент **не коммитит сам**, пока пользователь явно не попросил. Это правило проекта,
см. `instructions/safety.md`.

## Перед коммитом

### 1. Проверить, что попадёт в коммит

```powershell
git status
git diff --stat
```

**Обязательно** убедиться, что нет мусора:
- ❌ `Library/`, `Temp/`, `Logs/`, `obj/` — не должны попадать (проверить `.gitignore`)
- ❌ Секреты, API-ключи, `.env` с реальными значениями
- ❌ `.csproj`, `.sln`, `.user` — генерируются, в `.gitignore`
- ❌ `Builds/` — в `.gitignore`
- ❌ Шаблонные ассеты Unity (`Assets/Readme.asset`, `Assets/TutorialInfo/`) — служебные,
  удалены при переводе проекта на собственную структуру

### 2. Проверить `.meta`

```powershell
git status --short -- "*.meta"
```

Каждый новый/изменённый ассет должен иметь `.meta`. Ассет без `.meta` = битая ссылка
у всей команды.

**Правило:** `.meta` коммитится **всегда** и **в том же коммите**, что и сам ассет.
Никогда не удалять `.meta` вручную.

### 3. Проверить код

Компиляция чистая, тесты проходят, `read_console` пуст.
См. `test-workflow.md` и `unity-automation.md`.

## Структура сообщения коммита

```
<тип>(<область>): <описание в императиве>

<тело: зачем, а не что>

Refs: docs/stages/stage-NN-*.md
```

**Типы:**

| Тип | Когда |
|---|---|
| `feat` | Новая функциональность |
| `fix` | Баг |
| `refactor` | Перестройка без изменения поведения |
| `test` | Тесты |
| `docs` | Документация |
| `chore` | Инфраструктура, настройки, зависимости |
| `perf` | Производительность |
| `style` | Форматирование |

**Области** — по слоям проекта:
`core`, `gameplay`, `ai`, `net`, `ui`, `camera`, `audio`, `save`, `editor`,
`docs`, `infra`

### Примеры

```
feat(gameplay): добавить выносливость с бегом и восстановлением

Выносливость — первое реальное решение «рискнуть или отступить» в игре.
Расход при беге, восстановление при ходьбе, нулевая выносливость блокирует бег.

Чистая логика в PlayerStamina, EditMode-тесты на кривую.
Интеграция в PlayerController через IInputReader.

Refs: docs/stages/stage-01-movement-and-camera.md
```

```
chore(infra): добавить OpenCode-слой (AGENTS.md, opencode.json, agents, skills, docs)

Проект переведён на управляемую AI-assisted разработку:
проектный контракт, control plane, role-based subagents,
durable спецификации и stage-based delivery.
```

```
fix(core): отписывать IInputReader в OnDisable

Подписка на input actions не снималась, что приводило к утечке
и залипанию ввода после отключения компонента.
```

## Хорошие тела коммита

**Плохо:**
```
fix: починил баг
```

**Хорошо:**
```
fix(ai): враг перестаёт застревать в дверях

NavMeshAgent не получал recalculate path после того, как дверь
закрывалась. Путь пересчитывался только при смене цели.

Добавлен вызов RecalculatePath при изменении навигации.
```

Тело отвечает на **почему**, а не на «что». «Что» видно в diff.

## Частые ошибки

| Ошибка | Последствие | Правильно |
|---|---|---|
| Коммит без `.meta` | Битые ссылки у всех | Один коммит: ассет + `.meta` |
| Переименование ассета без `.meta` | Потеря всех ссылок | Переименовывать через Unity, не вручную |
| Коммит `Library/` | Огромный diff, тормоза | Проверить `.gitignore` |
| Коммит всего подряд | Неревьюимо | Осмысленный коммит = один инкремент |
| Коммит без ссылок на stage | Непонятно, к какой части работы относится | `Refs: docs/stages/...` |

## Ветки

Один разработчик: работаем в ветке по умолчанию (`master`/`main`),
stage-based инкременты коммитятся последовательно.

Несколько разработчиков: `feature/stage-NN-short-name` → merge.
Агент не создаёт и не переключает ветки без явной просьбы.
