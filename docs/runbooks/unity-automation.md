# Runbook — Unity MCP

## Статус: МОСТ НЕ НАСТРОЕН

> **Сейчас в проекте нет MCP-сервера для Unity.**
> `opencode.json` не содержит секции `mcp`. Все операции с Editor'ом выполняются
> вручную через UI Unity.

Это временное состояние. Планируется поставить **Unity MCP**
(`CoplayDev/unity-mcp`, MIT-лицензия) — пакет `MCPForUnity` в проект плюс
Python-сервер через `uvx`.

**Что нужно сделать после установки:**

1. Добавить секцию `mcp` в `opencode.json`.
2. Проверить, что сервер отвечает на `initialize`.
3. **Сверить реальные имена инструментов** с тем, что отдаёт сервер, и переписать
   этот файл, `AGENTS.md → Verification commands`, скиллы и команды.
4. Только после этого дописать `Required tests` и `Acceptance criteria` в stage files.

> **Почему так осторожно.** Этот проект уже дважды пережил «документацию по
> памяти»: описанные инструменты оказывались не у того сервера. Проверка
> фактическим вызовом — обязательное условие, а не рекомендация.

## Пока моста нет: как работать

### Компиляция

```
Assets → Refresh (Ctrl+R)
Window → General → Console, фильтр Errors
```

`Ctrl+R` инициирует перекомпиляцию. Console — источник правды об ошибках.

### Тесты

```
Test → Test Runner → EditMode → Run All
Test → Test Runner → PlayMode → Run All
```

PlayMode первый запуск долгий из-за перезагрузки домена — это нормально.

### Очистка консоли

```
Edit → Clear
```

### Сборка player

```
File → Build Settings → Build And Run
```

### Запекание света и NavMesh

```
Window → Rendering → Lighting → Generate Lighting
Window → AI → Navigation → Bake
```

### Ввод в Play Mode

Запустить Play Mode вручную и проверить клавиши вживую.

## Что нужно для полной автоматизации

Задачи, которые сейчас ручные, но станут автоматическими с мостом:

| Задача | Инструмент ожидается от Unity MCP |
|---|---|
| Компиляция | `refresh_unity` |
| Ошибки и логи | `read_console` |
| EditMode / PlayMode тесты | `run_tests` |
| Сборка player | `manage_build` |
| Сцена, иерархия | `manage_scene` |
| Объекты и компоненты | `manage_gameobject`, `manage_components` |
| Ассеты и префабы | `manage_asset`, `manage_prefabs` |
| Рефлексия по Unity API | `unity_reflect`, `unity_docs` |
| Профайлер | `manage_profiler` |
| Рендер и Volume | `manage_graphics`, `manage_camera` |

**Имена выше — ожидания, не факты.** После установки их нужно сверить с
реальным `tools/list` и исправить. Не использовать как есть.

## Проверка Unity API без моста

Пока нет `unity_reflect`, единственный способ — **не полагаться на память**
и проверять через официальную документацию:

```
https://docs.unity3d.com/6000.6/Documentation/ScriptReference/<ClassName>.html
```

Версия в URL должна совпадать с версией проекта из
`ProjectSettings/ProjectVersion.txt` (`6000.6.3f1`).

Менее надёжный, но быстрый способ: поиск по установленным пакетам в
`Library/PackageCache/` — исходники API там есть.

## Правила

| Правило | Почему |
|---|---|
| Не выдумывать имена инструментов и их параметры | Документация по памяти уже дважды вводила в заблуждение |
| Проверять API через документацию под версию проекта | Unity `6000.6.3f1` свежая, память устаревает |
| Не объявлять «готово» без фактического прогона тестов | Это единственный источник правды |
| Указывать в отчёте, что проверено, а что — нет | Иначе верификация фиктивна |

## Чего делать нельзя

- ❌ Править YAML Unity-ассетов (`.unity`, `.prefab`, `.mat`)
- ❌ Удалять `.meta` вручную
- ❌ Приписывать агенту инструменты, которых в его наборе нет
- ❌ Заявлять «тесты прошли», не прогнав их
- ❌ Заявлять «сборка собралась», не собрав её
