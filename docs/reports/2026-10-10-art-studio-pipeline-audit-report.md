# Отчёт — пайплайн генерации: двойная работа, область вырезки, шаги сэмплера

## Stage

Вне этапов (аудит инструмента генерации: `docs/specs/art-generation.md`,
стенд `F:\ai\portraits`).

## Objective

Три вопроса:

1. Не делается ли лишняя работа или работа дважды при генерации одного или
   нескольких новых портретов/фонов.
2. **Особое внимание:** скрипт вырезки обязан резать ТОЛЬКО те файлы, что
   сгенерировал этот прогон. Раньше был баг: на заказе из 1–2 картинок он
   проходил по всей папке.
3. Что такое «10 шагов» в параметрах генерации и можно ли их уменьшить.

## Ответы коротко

1. **Вырезка уже ограничена заказом.** Проверено на живых логах и на
   реальном прогоне: в `raw` 131 файл, заказ одного кадра → вырезан ровно
   **1**. Баг закрыт раньше (`--only`), но оставалась ловушка, из-за которой
   он мог вернуться, — она устранена.
2. **Нашлась настоящая двойная работа** — в перегенерации помеченного брака:
   каталог стенда пересобирался на каждую метку. Плюс молчаливый баг: две
   метки одного пула давали один id, то есть вторая перегенерация пропадала.
3. **Шаги 10 — итерации денойзинга.** Уменьшить можно, но выигрыш мал
   (≈1 с из 12), а главное — **правка была бы бесполезной**: генерацию вёл
   не тот словарь, который печатался в лог.

## 1. Область вырезки: доказательства

### Что говорит код

`shoot.py → cut_characters()`:

```python
names = {f"{c['id']}_{style}" for c in scene.CHARACTERS
         if not only or c["id"] in only}          # только заказанные id
todo = [(n, os.path.join(raw_dir, f"{n}.png")) for n in names]
todo = [(n, p) for n, p in todo if os.path.exists(p)]   # и только реально есть
if not todo:
    return 0                                      # нечего — seg.py не зовём вообще
...
"--only", *[f"{name}.png" for name, _ in todo]    # список уходит в seg.py
```

`seg.py`:

```python
files = [f for f in os.listdir(args.src) if fnmatch.fnmatch(f, args.pattern)]
if args.only is not None:
    wanted = set(args.only)
    files = [f for f in files if f in wanted]
```

Три уровня сужения: заказ → наличие файла → пересечение внутри `seg.py`.

Последние 12 прогонов: **вырезано ровно столько, сколько заказано.**
Строки `пакетный режим: 103 файлов` встречаются только дважды — в самых
старых записях лога (04:01 и 19:44), то есть это и есть тот баг, до правки.

### Проверка на живом стенде

```
в raw: 131 файл
$ seg.py raw C:/Temp/segtest --only 11_alchemist_ink.png
пакетный режим: 1 файлов -> C:/Temp/segtest
  [1/1] 11_alchemist_ink.png: покрытие 53.0%
готово
→ в каталоге ровно 1 файл
```

### Устранённая ловушка

`seg.py` объявлял `--only` как `default=()`. При таком объявлении **«флаг не
передан» и «флаг передан без значений» неотличимы** — оба дают пустой кортеж.
Значит `--only` без значений молча вырождался в «обработать всю папку» — ровно
тот баг, на который жаловались. Теперь `default=None`:

- флага нет → `None` → вся папка (осознанный запрос);
- `--only` без значений → `[]` → **ничего** + явное сообщение;
- `--only a.png b.png` → ровно эти файлы.

Проверено: `--only` без значений на папке `raw` (131 файл) больше не запускает
вырезку.

## 2. Двойная работа: что нашлось

### 2.1. Перегенерация пересобирала каталог на каждую метку (исправлено)

`regen_targets()` для каждой помеченной браком метки:

- `_stand_id_for_mark()` → `self.stand.catalog()` — **полный обход каталогов
  проекта по всем 88 пулам**;
- внутри того же обхода — `destination()` для **каждого** id (~120 штук);
- затем `free_ids(pool, 1)` → `catalog()` **ещё раз**.

Итого на N меток: `2N` пересборок каталога и `N × 120` вызовов `destination()`.

Стало: каталог строится **один раз** на команду, карта «путь → id» — тоже
один раз. Замер на трёх метках:

| | было | стало |
|---|---|---|
| `catalog()` | 6 | **1** |
| `destination()` | 9 | **3** |

### 2.2. Молчаливый баг: две метки одного пула → одна перегенерация

`free_ids(pool, 1)` каждый раз возвращал **первый** свободный id, поэтому две
метки одного пула получали один и тот же id, а `if stand_id not in targets`
отбрасывал второй. Человек помечал два кадра, перегенерировался один.

Теперь номер **забирается из списка** (`free.pop(0)`). Проверено: две метки
пула `p_Roles_Priest` дают `p_Roles_Priest_c` и `p_Roles_Priest_d`.

### 2.3. Устаревший файл мог быть принят за новый (исправлено)

`out` — накопительный каталог стенда. Приёмка проверяла только
`os.path.isfile(source)`. Если кадр сейчас не нарисовался (сбой, отмена,
отбраковка по засветке), одноимённый файл от прошлого прогона оставался на
месте — и **приёмка забрала бы старую картинку, выдав её за новую**.

Теперь `_is_fresh_output(path, run_started)`: время изменения файла обязано
быть позже начала прогона (допуск 1 с — от гранулярности файловой метки).
Проверено: старый файл → отказ, свежий → приём, отсутствующий → отказ.

### 2.4. Лишнее декодирование исходника (исправлено, стенд)

`shoot.py → cut_characters()` открывал `Image.open(src).convert("RGB")` для
**каждого** кадра, хотя в штатной ветке (маска от BiRefNet) результат не
использовался вообще — работа на каждый файл ради ничего. Открытие перенесено
в ветку отката на хромакей, где он действительно нужен.

### 2.5. Что проверено и НЕ является двойной работой

- **Генерация кадра** — ровно один `shoot_one` на id. Повторы бывают только по
  делу: крах (тот же сид) и кадр-шум (другой сид).
- **Фоны не вырезаются вообще** (`cut_characters` зовётся только для `chars`) —
  у фона нет хромакея.
- **`catalog()` в `cmd_generate`** вызывается один раз на команду.
- **Покрытие считается трижды** (в `seg.py`, затем в `shoot.py`, затем в
  драйвере), но это гистограмма по альфа-каналу 480×720 — доли миллисекунды.
  Оставлено: убирать значило бы ломать разделение слоёв ради ничего.

## 3. Шаги сэмплера: что это и можно ли уменьшить

### Что такое «10 шагов»

Шаги — это **итерации денойзинга**: сколько раз модель уточняет картинку,
двигаясь от чистого шума к изображению. Каждый шаг — один прогон
диффузионной сети. Больше шагов — тоньше детали и дольше счёт.

Стенд: `Z-Image` (потомок Lumina2), квант Q8_0 в GGUF, `euler_cfg_pp` /
`simple`, `cfg 1.0`. Модель **дистиллирована**, поэтому `cfg=1.0` и 10 шагов —
её штатный режим; негативный промпт при `cfg 1.0` не действует.

### Найденная ловушка: шаги правились не там

`shoot.py` **печатает** `scene.GEN['steps']`, а генерацию ведёт
**`gen.GEN['steps']`** — это два разных словаря (`scene.py` и `gen.py`).
`build_graph()` делегирует в `gen.build_workflow()`, а тот читает свой `GEN`.

Пока оба равны 10, расхождение незаметно. Но правка `scene.GEN["steps"]`
(очевидное место — именно оно светится в логе) **не изменила бы в генерации
ничего**, а лог бы соврал, показав новое число.

Исправлено: `shoot.py` перед прогоном синхронизирует
`gen.GEN["steps"] = scene.GEN["steps"]` (и `cfg`). Источник истины —
`scene.GEN`: там же стили, свет и промпты.

Проверено на графе: `KSampler` получает 10 по умолчанию и **6** после правки
`scene.GEN["steps"] = 6`.

### Стоит ли уменьшать

Замеры проекта (12 кадров 480×720):

| | Время |
|---|---|
| кадр с **1** шагом | 26.2 с |
| кадр с **10** шагами | 28.5 с |

Разница между одним и десятью шагами — **2–3 с**, то есть **≈0.26 с на шаг**.
Почти всё время кадра — фиксированные накладные расходы: загрузка весов,
энкодинг промпта, VAE. После снятия `--cache-none` кадр стоит ~10–12 с.

Отсюда: **10 → 6 шагов сэкономит ≈1 с из 12 (~8 %).** Шаги — не то место, где
лежат секунды. Настоящие рычаги: держать сервер тёплым (−34 с на холодном
старте) и не пересчитывать вырезку по всей папке.

Если всё же пробовать: начинать с 8 и сравнивать глазами — модель
дистиллирована, но LoRA и стиль могут просесть по мелкой детали.

## Verification performed

- `py_compile` — `artgen.py`, `seg.py`, `shoot.py`: **OK**.
- `seg.py --only <1 файл>` при 131 файле в `raw` → вырезан **1**.
- `seg.py --only` без значений → «вырезать нечего», папка не тронута.
- `regen_targets` на 3 метках: `catalog()` 6 → **1**, две метки одного пула →
  два разных id.
- `_is_fresh_output`: старый/свежий/отсутствующий/прогон позже файла — все
  четыре случая верны.
- Граф: `KSampler` получает steps из `scene.GEN` (10 → 6 после правки).
- Unity `read_console(types:["error","exception","warning"])` = **0**.
- EditMode — изменений C# не было, набор не перезапускался.

## Not verified

- **Полный живой прогон с GPU** после правок не запускался: это минуты
  нагрузки, а ComfyUI сейчас погашен. Проверены логика и граф, а не реальная
  вырезка/генерация через окно.
- Выигрыш от уменьшения шагов **не измерен** на живом стенде — цифра ≈1 с
