# ADR 0004 — ScriptableObjects for Design Data

## Status

Accepted

## Date

2026-09-30

## Context

Игра содержит данные, которые настраивает дизайнер без участия программиста: параметры
врагов, характеристики предметов, настройки уровней, кривые выносливости, параметры камеры.

Нужно решить, где живут эти данные и как они попадают в рантайм.

Варианты, которые отвергаются:
- **Всё в коде** — дизайнер не может настроить, каждое изменение требует программиста
- **JSON/CSV в `StreamingAssets`** — рантайм-парсинг, валидация в рантайме, опечатки в ключах
  ломают игру в рантайме вместо редактора
- **`Resources.Load`** — блокирует сборку, не масштабируется, трудно найти кто что грузит
- **Адресаблы** — правильное решение для крупных проектов, но для набора из ~20 ассетов
  это лишняя сложность и лишняя зависимость

## Decision

### ScriptableObject — единственный способ хранения дизайн-данных

Типы данных наследуют `ScriptableObject`. Ассеты лежат в
`Assets/Woodberry/Settings/` (или подкатегории), редактируются в инспекторе.

### Правила

1. **SO — только дизайн-данные, никогда runtime-состояние.**
   Runtime-состояние (текущее здоровье, позиция, кулдаун) живёт на компонентах и сервисах.
   Причина: SO — ассет, общий для всех экземпляров. Изменение в нём в рантайме
   затронет все экземпляры сразу. Это типичный баг.

2. **Ссылки хранятся в инспекторе, не ищутся в рантайме.**
   SO-конфиг — это ссылка на другой SO, проставленная в инспекторе.
   Никаких `FindObjectOfType` для дизайн-данных.

3. **`OnValidate` проверяет инварианты.**
   Некорректные данные должны ломаться в редакторе, а не в игре.

4. **Имя файла = имя типа** (ADR 0001), ассет — `PascalCase` + `Definition`/`Config`:
   `Enemy_Zombie.asset`, `ItemDefinition_Flare.asset`.

5. **SO неизменяем в рантайме.** Нужен другой баланс — создай новый SO,
   а не мутируй существующий.

6. **`CreateAssetMenu` — только когда ассет создаётся вручную.**
   Если ассет — часть контента и не должен появляться случайно, `CreateAssetMenu` не нужен.

### Пример структуры

```csharp
namespace Woodberry.Gameplay.Enemies
{
    [CreateAssetMenu(
        fileName = "Enemy_Definition",
        menuName = "Woodberry/Enemy Definition")]
    public sealed class EnemyDefinition : ScriptableObject
    {
        [SerializeField] private string _displayName;
        [SerializeField, Min(1f)] private float _maxHealth = 100f;
        [SerializeField, Min(0f)] private float _moveSpeed = 2f;
        [SerializeField] private float _perceptionRadius = 12f;

        public string DisplayName => _displayName;
        public float MaxHealth => _maxHealth;
        public float MoveSpeed => _moveSpeed;
        public float PerceptionRadius => _perceptionRadius;

        private void OnValidate()
        {
            if (_maxHealth <= 0f)
            {
                Debug.LogError($"[{nameof(EnemyDefinition)}] MaxHealth должен быть > 0", this);
            }
        }
    }
}
```

## Consequences

### Positive

- Дизайнер настраивает без программиста
- Ошибки в данных ломаются в редакторе, а не в игре
- Ссылки видны в инспекторе, не ищутся в рантайме
- Нет `Resources.Load` — сборка не блокируется
- Данные версионируются в git как текст, diff читаем

### Negative

- Нет валидации на этапе сборки. Ошибка в SO всплывёт только в редакторе.
  Митигация: `OnValidate` + отдельный Editor-валидатор (см. `Assets/Scripts/Editor/`)
- SO-ассеты не сериализуются в билд автоматически, если на них нет ссылок.
  Митигация: ссылки проставляются в инспекторе — значит, попадут.
- Runtime-состояние всё равно нужно хранить отдельно. Два места хранения данных —
  это цена разделения. Митигация: явное правило «SO = дизайн, компонент = состояние».
- Для очень большого объёма данных SO не масштабируется → тогда Addressables.

## Alternatives considered

### Addressables

Правильное решение для проектов с сотнями/тысячами ассетов и адресуемой загрузкой.
Для нашего набора — лишняя сложность и зависимость. **Вернуться, когда** появится
динамическая загрузка контента или размер билда станет проблемой.

### JSON в `StreamingAssets`

Отклонено: рантайм-парсинг, ошибки в ключах ломают игру в рантайме, нет валидации в редакторе.

### Всё в коде

Отклонено: дизайнер блокирован.

## Revisit when

- Появится динамическая загрузка контента (нужны Addressables)
- Число SO-ассетов превысит ~100 и управлять ими вручную станет тяжело
- Размер билда станет проблемой
