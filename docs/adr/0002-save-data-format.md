# ADR 0002 — Save Data Format

## Status

**Accepted** (2026-10-07)

Решение фактически принято: формат JSON, ручная сериализация через DTO,
версионирование через поле `version`, атомарная запись, автоматическая
миграция. Все открытые вопросы закрыты. Контракт для кода — в
`docs/specs/save-system.md`. Разделение на сейв персонажа и сейв мира —
`0011-character-and-world-saves.md`.

## Date

2026-09-30

## Context

Нужно сохранять состояние мира и прогресса игрока. Решения, которые надо принять  
заранее, потому что они влияют на `Gameplay`-слой:

1. Формат файла
2. Что сохраняется, а что — нет
3. Версионирование и обратная совместимость
4. Атомарность записи

Формат выбирается до того, как появится первая реальная сейв-функция: миграция  
собственного формата на наборе данных дороже, чем выбор правильного формата изначально.

## Decision

**Предлагается:** ручная сериализация в JSON через DTO-классы, версионирование  
через поле `version`, атомарная запись через временный файл + переименование.  
Подробности — в `docs/specs/save-system.md`.

Обоснование JSON: читаемость, diff при версионировании в git, отсутствие зависимости  
от версии Unity. Обоснование ручной сериализации вместо `JsonUtility`: `JsonUtility`  
не поддерживает полиморфизм, не даёт версионирования и падает на нетривиальных структурах.

### Миграция сейвов

**Мигрируем автоматически.** При загрузке сейв старой версии конвертируется в  
текущий формат: код читает `version`, прогоняет цепочку преобразований  
`v1 → v2 → v3` и только потом отдаёт данные игре.

Почему не «отказывать»: сейв — это десятки часов игры. Патч, обнуляющий  
прогресс, читается игроком как поломка, а не как правило.

**Следствие для работы:** каждая смена схемы сейва обязана оставлять шаг  
миграции и тест на него. Без шага миграции версия не выпускается — иначе первый  
же игрок со старым сейвом получит сломанный профиль.

**Это не то же самое, что расхождение версий в кооперативе.** Там гость с  
версией ниже в сессию не пускается — см. `0011-character-and-world-saves.md`.  
Причина разная: свой сейв мигрируем, чужую игру — нет.

## Открытые вопросы

- [x] Слоты — решено: **несколько слотов**, не одно автосохранение.
- [x] Синхронизация сейва с сессией — решена в  
  `0011-character-and-world-saves.md`: переносится персонаж, а не сессия.
- [x] Миграция при смене версии — решено: **мигрируем автоматически**, цепочкой  
  `v1 → v2 → …` при загрузке.
- [x] Предупреждать игрока — не нужно: миграция незаметна.

## Consequences (если принято)

### Positive

- Читаемый diff при версионировании сейв-схемы
- Старый сейв открывается новым кодом
- Безопасно при обрыве записи

### Negative

- Ручные DTO-классы дублируют структуры — код растёт
- Нужна дисциплина: DTO не должны содержать Unity-типы, которые не сериализуются

## Revisit when

- Появится большой объём сохраняемых данных (> 1–2 МБ)
- Требуется сжатие или шифрование
