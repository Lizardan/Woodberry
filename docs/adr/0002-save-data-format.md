# ADR 0002 — Save Data Format

## Status

Proposed

## Date

2026-09-30

## Context

Нужно сохранять состояние мира и прогресса игрока. Решения, которые надо принять
заранее, потому что они влияют на `Gameplay`-слой:

1. Формат файла
2. Что сохраняется, а что — нет
3. Версионирование и обратная совместимость
4. Атомарность записи

Формат выбирается до того, как появится первая реальная сейв-функция: миграция
собственного формата на наборе данных дороже, чем выбор правильного формата изначально.

## Decision

**Предлагается:** ручная сериализация в JSON через DTO-классы, версионирование
через поле `version`, атомарная запись через временный файл + переименование.
Подробности — в `docs/specs/save-system.md`.

Обоснование JSON: читаемость, diff при версионировании в git, отсутствие зависимости
от версии Unity. Обоснование ручной сериализации вместо `JsonUtility`: `JsonUtility`
не поддерживает полиморфизм, не даёт версионирования и падает на нетривиальных структурах.

## Consequences (если принято)

### Positive

- Читаемый diff при версионировании сейв-схемы
- Старый сейв открывается новым кодом
- Безопасно при обрыве записи

### Negative

- Ручные DTO-классы дублируют структуры — код растёт
- Нужна дисциплина: DTO не должны содержать Unity-типы, которые не сериализуются

## Revisit when

- Появится большой объём сохраняемых данных (> 1–2 МБ)
- Требуется сжатие или шифрование
